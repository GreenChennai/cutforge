# ADR-0022:ffmpeg 策略——安装器可选组件(默认勾选内嵌),运行时 env→系统 PATH→内嵌,缺失给 doctor 级修复指引

日期:2026-09-30 · 状态:已采纳(册六 D-F2,动工前落库)
关联:册六迭代计划 T6.4/D-F2 · doctor(可复制执行修复命令口径)· probe.rs(唯一外部进程调用点)· ADR-0020(渲染确定性依赖 ffmpeg 行为)· ADR-0010(个人自用)

## 背景

渲染/探测/导出全链依赖 ffmpeg/ffprobe 外部二进制。现状:env `CUTFORGE_FFMPEG`/`CUTFORGE_FFPROBE` 显式覆盖 → 系统 PATH 探测;纯净 Windows 机器两者皆缺,"装完即用"不成立。决策点 D-F2:强制内嵌 vs 仅系统依赖 vs 安装器可选组件。

## 决策

1. **内嵌作为安装器可勾选组件,默认勾选**:安装器(T6.4 落地)把构建机 ffmpeg/ffprobe 随包携带至安装目录 `bin/`,体积代价 +40–80MB;不想要的用户安装时取消勾选(便携版 zip 天然内嵌)。
2. **运行时解析顺序 = env 显式覆盖 → 系统 PATH → 内嵌随包**:显式 env 最高(调试/多版本切换);系统 PATH 次之(用户自装的 ffmpeg 通常更新,且与既有 e2e/parity 行为零变化);内嵌兜底(勾选组件在位即命中)。任一环命中即用;解析结果(env/path/embedded)进 doctor 如实报告。内嵌命中方式 = 安装器写 `CUTFORGE_FFMPEG`/`CUTFORGE_FFPROBE` 指向安装目录——运行时探测面零新代码,无新配置文件格式。
3. **无 ffmpeg 且未勾选内嵌 → doctor 级修复指引**:启动体检与 `cutforge-cli doctor` 的 ffmpeg/ffprobe 检查项给可复制执行的修复命令(重跑安装器勾选内嵌 / winget 安装 / setx env 三选一),DEP_MISSING 语义不变——缺依赖是环境事实,报错不猜。

## 取舍

- 不强制内嵌:+40–80MB 挂在每个安装包上,且 ffmpeg 升级节奏被安装器发布周期绑死;内嵌定位是"纯净机兜底"而非"首选解释器"。
- 内嵌排在 PATH 之后:系统 ffmpeg 是用户可见可升级的现实;优先内嵌会让"我明明装了新版 ffmpeg 为什么没用上"成为必然工单。确定性敏感面(像素对拍/parity)本就按"同机同 PATH"口径成立,不因解析顺序改变。
- 运行时零新增探测代码:内嵌的"在位"由安装器写 env 表达,probe/doctor 既有面直接覆盖;册六后端只扩 doctor 报告文案与解析来源标注,内嵌物理落包归 T6.4 安装器。

## 被否决的替代

- **强制内嵌(唯一来源)**:否决——体积与更新负担全随包,用户自装 ffmpeg 反而失效;违背个人自用"机器说了算"的弹性。
- **仅系统依赖(不内嵌)**:否决——纯净机(AC-6.5/6.6 验收机)不满足"装完即用",独立化叙事在第一跳就断。
- **随包 DLL 动态加载/进程内 libav**(*-sys crate 绑定):否决——新增 Cargo 依赖违反依赖纪律,且把 ffmpeg 版本焊进二进制,升级=重发版;子进程隔离还保住"渲染崩溃不拖死编辑器"。

## 后果

- doctor 的 ffmpeg/ffprobe 检查项修复指引扩为三选一(安装器内嵌 / winget / env),并标注解析来源(env/path)。
- T6.4 安装器组件清单含 ffmpeg 勾选项(默认勾),写 env 的具体键名以本决策为准。
- 纯净机全流程(AC-6.6)的依赖前提由内嵌组件满足;e2e/parity 在有 PATH ffmpeg 的开发机上行为不变。
