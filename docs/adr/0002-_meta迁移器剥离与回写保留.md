# ADR-0002:`_meta` 采用"迁移器剥离 + 回写保留"旁路

日期:2026-09-19(M8)· 状态:已接受 · 关联:ITERATION-PLAN-v2.0 D2/P0-2

## 背景

CutFlow 的 `rs_ir.py build` 两个路径**必写**顶层 `_meta`(generatedFrom/keepSegments/
finalDurationMs/…,含 B8 手注护栏的 `manualEdit` 语义)。cutforge 的 project.schema.json
顶层 `additionalProperties:false` 且无 `_meta` 定义 → `Workspace::open` 对**任何**
CutFlow 真实生成的工程直接失败:"未通过 v2 契约: additionalProperties=false 拒绝多余键
'_meta'"。结合面完全断裂:CutForge 打不开它要精修的唯一上游产物。

## 决策

- **`_meta` 不进契约**。open 时剥出 `_meta` 存 Workspace 内存旁路(`meta_bypass`),
  契约校验/Engine/OpLog 全程不见它;`persist()` 序列化后原样回写。
- 合并(`merge_from_disk`)时磁盘若带新版 `_meta`(CutFlow 重新生成过 IR),
  采纳磁盘版本——它是外部生产者的新鲜状态。
- 门禁 M8-2:夹具由 `tools/gen_real_ir_fixture.py` 调 **CutFlow rs_ir.py 真实 build**
  生成(非手写),open→apply→reopen→roundtrip 后 `_meta` 逐字节相等。

## 否决的替代方案

- **schema 显式收录 `_meta` 为保留字段**:把 CutFlow 的实现细节(含 manualEdit
  护栏语义)耦死进两仓契约,`_meta` 每加一个键都要发 schema 版本;旁路保留成本
  约十行代码且零契约面。
- **让 CutFlow 停写 `_meta`**:上游语义(manualEdit 护栏、溯源)有真实消费者,
  不可为下游方便而破坏。

## 后果

- CutForge 打得开任何真实 CutFlow 工程,写回不丢其元数据(夹具锁定)。
- 代价:`_meta` 在 cutforge 侧无 schema 保护,格式错误只能由上游 validate 负责
  ——可接受,它本来就是上游实现细节。
- 术语记录见 CutFlow CONTEXT.md(V2 审查时补):文件级 Op / 基线快照 / `_meta` 旁路。
