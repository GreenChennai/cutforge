# ADR-0015:画布自定义——宽高扩为范围约束(64–7680 偶数)+ 常用预设,不再锁三值枚举

日期:2026-09-29 · 状态:已采纳(册四 D-D1,动工前落库)
关联:册四迭代计划 T4.9/D-D1/AC-4.8 · FLOW.md §5.6(渲染缓存键已含画幅)· schemas/constants.ratios.json(canvasAllowed 生成口径)· G3-5 漂移门禁 · ADR-0010(个人自用)

## 背景

契约现状:`project.schema.json` 的 `canvas.width/height` 是三值枚举 [1080, 1440, 1920],由 `tools/gen_constants.py` 从 `rs_common.RATIOS + platforms.json` 生成,`mcp-tools.json` 的 `new_project.canvasW/canvasH` 同枚举,漂移由 G3-5 门禁阻断。三值是 CutFlow 口播时代的平台适配遗产(横/竖/方),到册四 T4.9"画布与构图"成为锁死项:2160×3840 竖屏高清、1440×1440 方图、4K 横屏等合法构图需求全部被 SCHEMA_INVALID 拒绝。计划书 D-D1 要求动工前定夺:扩宽还是保持枚举。

## 决策

1. **宽高从三值枚举扩宽为范围约束**:width/height 各自 `64 ≤ 值 ≤ 7680`,且**必须为偶数**(渲染链 yuv420p/x264 对奇数尺寸直接报错,约束前移到 schema,超界在 SCHEMA_INVALID 拒绝,不进渲染)。fps 枚举(24/25/30/50/60)本 ADR 不动。
2. **常用预设走 UI 不走契约**:画布设置面板提供 1080×1920(9:16)/ 1920×1080(16:9)/ 1080×1080(1:1)/ 3840×2160(4K)/ 自定义输入五档;预设是壳交互便利,契约只认范围约束——新增预设零 schema 改动。
3. `constants.ratios.json` 的 `canvasAllowed` 语义从「合法集」调整为「预设推荐集」(gen_constants.py 生成口径同步),G3-5 门禁改为校验「schema 范围约束与生成物口径一致」而非逐值比对。

## 影响面评估(决策前提,逐项落档)

- **多画幅变体(outputs)**:`outputs` 是比例语义枚举(9x16/3x4/16x9),不持具体分辨率;自定义主画幅下变体目标分辨率 = 比例 × 主画幅基准边等比推导,reframe 渲染端本就按目标画幅工作,**零新增通道、outputs 枚举不动**。非标准比例(如 21:9)不在本 ADR 范围——那是 outputs 枚举扩展,届时另议。
- **渲染缓存键**:FLOW.md §5.6 五层内容寻址缓存键 = hash(输入 spec)+RENDERER_VERSION+**相关画幅/帧率**——画幅已在键内,自定义值天然产生不同键,**缓存零重构**;真正的风险是"无界输入 → 键空间爆炸 + 垃圾条目挤占 LRU",由范围约束收敛(这是否决完全无界的直接原因)。
- **schema 校验**:`project.schema.json` width/height 改 `minimum: 64 / maximum: 7680` + 偶数约束;`mcp-tools.json` canvasW/canvasH 同步同约束(单源经 gen_constants 生成面,防两端漂移);Python 侧 `tools/_generated/cf_validate.py` 随 schema_gen 重生成,双端对拍回归集补边界样本(64/66/7678/7680 通过,63/65/7681 拒绝)。
- **预览画布适配**:壳预览与检查器的画布 fit 以**投影 `project.canvas` 为唯一依据**,核查并清除按三值假设写死的缩放/贴纸坐标常量;画布内拖拽(pip/文本/九宫格吸附)一律用投影宽高换算。

## 取舍

- 范围 + 偶数 + 预设的组合,把"自由"约束在**可判定、可缓存、可渲染**的盒子内:上界 7680 覆盖 8K 等效长边,下界 64 排除病态值;偶数是渲染链物理约束而非产品口味,写进 schema 让错误在最便宜的位置暴露。
- 代价:G3-5 门禁与 gen_constants.py 生成口径要动一次;边界样本进回归集是长期维护面(约 6 个用例,可控)。
- 个人自用场景(ADR-0010)下不存在"恶意输入"方,范围约束防的是**自己的手滑**(手输 7639×4321 这类奇数/超界),schema 报错信息即自解释。

## 被否决的替代

- **保持三值枚举**:否决——构图自由被锁死,与 T4.9 画布设置目标直接冲突;每支持一个新尺寸都要动 schema + 门禁 + 两端对拍,扩张成本反而更高。
- **完全无界(任意正整数)**:否决——缓存键空间随输入无界膨胀、垃圾条目挤占 LRU(10GB 上限被病态值吃穿);奇数/超大值会穿透 schema 到 ffmpeg scaler 才失败,错误暴露在最贵位置;预设与校验提示也无从谈起。

## 后果

- 新画布值进工程即受 G3-5 门禁与双端对拍约束;超范围/奇数在 SCHEMA_INVALID 拒绝,渲染链可假设"画幅合法且偶数"。
- `canvasAllowed` 推荐集语义变化会波及引用它的判定/生成代码——动工时以 grep 盘点消费方,只允许"推荐清单"类消费。
- 后续任何"再加一个预设"零契约改动(壳 UI 层即可),契约改动只在"改范围边界"时发生。

## 落地证据(动工后核销)

- `schemas/project.schema.json`(canvas 范围约束)、`schemas/mcp-tools.json`(canvasW/canvasH)、`tools/gen_constants.py` 与 `schemas/constants.ratios.json`(canvasAllowed→推荐集口径)。
- `crates/` 侧 schema 引擎与 G3-5 门禁判定、`tools/_generated/cf_validate.py` 重生成、双端对拍边界样本。
- `apps/web` 画布设置面板(五档预设 + 自定义)与预览 fit 以投影 canvas 为唯一依据的核查记录。
