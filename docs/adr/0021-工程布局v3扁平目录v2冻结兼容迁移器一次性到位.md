# ADR-0021:工程布局 v3(扁平目录)——v2 读写冻结兼容 + 迁移器一次性到位

日期:2026-09-30 · 状态:已采纳(册六 D-F1,动工前落库)
关联:册六迭代计划 T6.1/AC-6.2/D-F1/F-R1 · docs/PROJECT-FORMAT.md(布局契约同步点)· paths.rs(目录契约唯一真相源)· ADR-0006(独立化定位)· ADR-0010(个人自用)· ADR-0013(派生物不入真相源)

## 背景

现役目录契约 v2(0.5 中文目录)沿袭 CutFlow 的**阶段叙事**:`00_制作简报`→`06_成片输出` 编号目录表达"口播→粗剪→成片"的流水线阶段。独立化(册六)之后,CutForge 是完整独立剪辑工具:阶段编号对独立用户是噪音,素材管理(一个 media 目录)与导出产物(exports)才是自然的心智。决策点 D-F1:是否引入 v3 扁平布局。收益 = 去掉阶段叙事、素材/导出面自然;代价 = 双布局维护与迁移面。

## 决策

1. **做 v3 扁平布局**。工程根即工程:真相源全部在根(`project.json` / `wordline.json` / `cutlist.json` / `cutlist.applied.json` / `notes.json`),素材 `media/`,导出 `exports/`,状态 `.cutforge/`(不变)。目录名唯一真相源仍是 `cutforge-io::paths`(新增 `V3_*` 常量与三态判定)。
2. **v2 兼容读写冻结(F-R1)**:迁移窗口内 v2(与 0.4.x 英文 v1)工程**原地兼容读写,不做双写**;旧布局读写路径只修 bug、不加能力。v3 是单向目标——不做 v3→v2 回迁(需要时从快照/git 自救)。
3. **迁移器一次性到位且幂等**:`cutforge-cli migrate <工程> --to v3` / MCP `migrate_layout`。映射按 paths 真实契约:`01_原始素材→media/`、`05_时间线工程/{project,wordline}.json→根`、`04_粗剪决策/{cutlist,cutlist.applied}.json→根`、`06_成片输出→exports/`;0.4.x 英文目录工程同映射(LEGACY_* 源)。契约文件搬完即腾空删除目录;非契约残留文件原地保留并在报告如实列出。`.cutforge/`(oplog/rev/快照/缓存)、`notes.json` 本就随根,原地不动——OpLog 完整性零影响。幂等:v3 工程再跑 = NOOP;预检发现任一目标已存在 → 整体拒绝(CONFLICT),绝不半迁移。
4. **落地节奏(过渡期显式开关)**:本册 `scaffold` 缺省**仍产 v2**——既有 19 份 e2e/夹具/壳侧断言全部锚定 v2 中文目录名,一次性翻缺省会把回归面炸成"叙事永存"的反面(为过测试而批量改断言)。v3 经三个显式入口启用:`cutforge-cli new --layout v3`、MCP `project_new layout="v3"`、`migrate --to v3`。缺省翻转(新工程一律 v3)待壳侧工程库页与安装器(T6.4)收编 v3 后单独变更并同步 e2e——登记为遗留,不在本册偷偷翻。

## 取舍

- v3 的媒体面语义从"01_原始素材(只读上游)"变为"media/(独立工程的素材池)":独立模式下素材本来就该进工程,`media/` 是新素材的落点与 `media_browse` 的默认视图;迁移把原素材目录整体改名,历史相对路径 `src` 由此继续成立(`01_原始素材/x.mp4 → media/x.mp4`,project.json 内相对引用随映射同步改写)。
- `00_制作简报 / 02_转写与校对 / 03_创作素材 / _内部状态` **原地保留不强迁**:它们是 CutFlow 上游输入与阶段叙事残留,v3 契约不收编;迁移器如实报告 kept,不发明"简报该去哪"的伪语义。
- 迁移后的工程**不再被 CutFlow 侧 rs_* 桥按 v2 契约识别**(CutFlow rs_paths.py 冻结于 v2)——这不是缺陷,是独立化的语义本身;ADR-0006 定位升级的自然结论。
- 双布局维护成本被三道闸压住:布局判定收敛在 paths 单点;Workspace::Layout 打开时判定一次、生命周期一致;旧布局只修 bug 不加能力。

## 被否决的替代

- **维持 v2(不引入 v3)**:否决——阶段叙事与独立化定位直接冲突,素材管理顶着"01_原始素材"的名字做"素材池"的事,叙事永存等于把 CutFlow 的历史包袱背到底。
- **只加不改、零迁移**(v2 目录继续用,新加 exports/ 平级):否决——两套目录语义并存比双布局更糟:迁移器仍迟早要来,而"半扁平"状态把映射规则搅成逐案判断;迁移窗口不会更短,只会更糊。
- **本册立即把 scaffold 缺省翻为 v3**:否决——19 份 e2e/夹具断言中文目录名,同步改断言属于"为过测试改断言"的反模式;过渡期显式开关(决策 4)让 v3 可用、可验证、可迁移,缺省翻转有独立的收编前提。

## 后果

- paths.rs 增三态判定(`LayoutKind::Legacy/V2/V3`)与 V3 常量;打开/落盘/导出产物路径按盘面布局解析(`output_dir` 等)。
- PROJECT-FORMAT.md 增 v3 布局契约节(映射表 + 冻结口径);迁移器报告含 moved/kept/removedEmptyDirs 逐项清单。
- 工程库(T6.1)的新建/复制以 v2 为缺省形态、接受显式 v3;快照与崩溃恢复对三态布局同构(`.cutforge/` 在三态中不变)。
- 遗留登记:缺省布局翻转为 v3(前提:壳工程库页 + 安装器收编 v3,e2e 断言同步);CutFlow 侧桥接对 v3 工程的显式提示。
