# ADR-0017:音频分离(人声/伴奏)册四不做,延后册五按三条标准评估,不做"永久不做"承诺

日期:2026-09-29 · 状态:已采纳(册四 D-D3,动工前落库)
关联:册四迭代计划 T4.8/D-D3 · 计划书 §4.F E-R1(代码依赖逐案 ADR)· ADR-0010(个人自用闭源非商业定位)· FLOW.md 能力矩阵(诚实标注口径)

## 背景

T4.8 音频工具清单把"人声/伴奏分离"列为可选并注明"外部模型,决策点"(D-D3)。候选实现 demucs / UVR 均为本地推理路线:模型权重数百 MB 级、附带各自的代码与模型许可证,CPU 推理有真实时延。CutForge 定位是个人自用闭源非商业(ADR-0010),最小依赖纪律(§4.F E-R1)要求代码依赖逐案 ADR;册四工期已满载(转场 50+ / 特效注册表 / 文本字幕全链)。动工前必须定夺:册四引入、延后评估、还是永久不做。

## 决策

**册四不做音频分离,延后册五评估。册四音频工具面 = 波形 / 音量 / 淡入淡出 / 降噪(afftdn)/ 变调 / 卡点,不含分离**——契约、渲染链、UI、门禁四处均不预留分离字段的半成品。

册五评估标准(**三条全部达标才立项;任一不达标则落"明确不做"结论并在能力矩阵诚实标注**,与"未评估"状态严格区分):

1. **体积与授权**:模型权重实际体积(预期数百 MB 级)与 demucs/uvr 代码、模型双许可证,可否随闭源个人项目本地使用——落档书面结论,不接受"应该可以";
2. **CPU 推理时延**:目标曲目(3–10min,B 站教程口径)在本机纯 CPU 的分离耗时有实测数字且可用(无 GPU 依赖,个人机器配置即验收环境);
3. **个人自用收益**:存在真实用例(给自己的素材做人声/伴奏分离),而非"剪映有所以要有"的伪需求对照。

## 取舍

- 延后不是搁置:评估标准在本 ADR 一次性写死,册五只需逐条填实测值,避免"到时候再想"的决策漂移;三条标准里授权与时延是硬门槛,收益是方向门槛。
- 册四音频面其余六项(波形/音量/淡入淡出/降噪/变调/卡点)全是 ffmpeg 滤镜域或纯算法(旧版 rs_beat 吸收),零外部模型依赖——把 T4.8 的工期让给这些确定性高的项,AC-4.6 验收不因分离项稀释。
- 个人自用定位下"功能不全"不是成本,"依赖不清"才是:一个授权含糊的数百 MB 模型混进闭源个人仓库,清理成本远高于晚一年再做。

## 被否决的替代

- **册四直接引入**:否决——体积/授权未评估就进依赖,直接违反 E-R1 逐案纪律;且 T4.8 满工期,引入只会挤压文本字幕这个真正的最大缺口(T4.7)。
- **永久不做、就此关闭**:否决——关闭了可能性:demucs/uvr 的模型体积与推理速度在演进,本机硬件会更换,三条标准完全可能未来全达标;"明确不做"必须是评估后的结论,不能是评估前的预支。
- **册四埋字段、渲染降级占位**:否决——契约半成品字段(有字段无实现)违反"操作 → IR → 成片三方一致"的册四总纪律,徒增对拍与文档谎言面。

## 后果

- 能力矩阵与册四验收清单(AC-4.6)不含分离项;若册五评估不达标,以"明确不做 + 原因(三条标准哪条未过)"落档,诚实标注口径与"延后""未评估"三分。
- 本 ADR 是 E-R1"代码依赖逐案 ADR"在册四的第一次行使:结论是"本案不进",下次外部模型类依赖(如 T5 之后的 AI 生成类)沿用同一评估框架(体积/授权/时延/真实收益)。
- 册四音频工具有任何"分离替代品"(如 afftdn 人声增强预设)按普通滤镜功能对待,与分离无契约关系。

## 落地证据(动工后核销)

- 册四能力矩阵/验收清单核对:分离不在册四工具面;AC-4.6 判定项与 T4.8 六项一一对应。
- `docs/` 册五规划面引用本 ADR 三条评估标准(体积与授权 / CPU 时延实测 / 真实用例)。
