# ADR-0010:定位转向个人自用、闭源、非商业——许可简化路径

日期:2026-09-27 · 状态:已采纳(总纲 §0.4 C3 既定动作,册一收官落地)
关联:ADR-0006(定位升级为可独立起步的编辑器) · ADR-0008(只学方法不复制代码,同一纪律) · `NOTICE.md` · README「许可」节 · 多册迭代总纲「使用定位」/ C3

## 背景

现状是混合授权:原创核心适用 **ARL-1.0**(弱传染,核心文件的修改须按协议第 3 条回传开源),
参考吸收来源 OpenCut / OpenCut Classic 为 **MIT**(归属见 `NOTICE.md` 第一节 +
逐字保留的 `LICENSE-OPENCUT.MIT`);文档同时声明「正式发布前协议文本尚待执业律师复核」
——这是 M0 立项时面向**公开发行**的合规口径。

用户已明确声明:本项目后续转向**个人使用、闭源、非商业**,不再以公开发行为目标;
多册迭代计划(总纲「使用定位」)已按此口径书写。本 ADR 把这一转向落为正式决策,
并写清许可义务的简化路径与不可触碰的边界。

## 决策

1. **定位**:CutForge 自本决策起定位为**个人自用 / 学习软件**,闭源使用、非商业;
   不做公开发行、不对外作出许可承诺,不再围绕公开发行维护合规流程。
2. **许可简化路径 = 流程简化,不改文本**:`LICENSE`(ARL-1.0)/ `NOTICE.md` /
   `LICENSE-OPENCUT.MIT` 三件套**原样保留,一字不改**——它们描述的是「若分发」时的条款,
   保留文件本身不产生新义务;不新拟闭源协议文本,不追加新的许可审批环节。
3. **律师复核义务的适用范围变化**:「发布前须执业律师复核」从「每次公开发行的硬前置」
   变为**挂起**——仅当未来恢复对外公开发行时重新成为前置项;纯自用、不分发的场景下
   该义务不被触发(ARL 的回传义务按其文本同样以分发为触发。本段是工程定位说明,
   不构成法律意见)。

## 不触碰项

1. **已发布 MIT 版本不可撤回**:CutFlow 历史上以 MIT 发布的版本(`v0.1.0`–`v0.12` 等 tag)
   上他人已获得的授权继续有效;本决策不撤回、不追溯任何已授予的许可。
2. **MIT 来源归属保留**:OpenCut / OpenCut Classic 的归属说明(`NOTICE.md` 第一节 +
   `LICENSE-OPENCUT.MIT` 逐字保留)继续随仓维护;「只吸收方法与能力、不复制源码」的边界
   (ADR-0008)不变。持续合规成本维持「一行 NOTICE」量级。
3. **本仓已发行 tag**(v0.1.0–v0.5.0)按各发行时点的条款效力不变;本决策仅声明后续工作的定位。

## 后果

- 正面:不再承担「面向公众发行」的流程成本(律师复核前置、发布前合规检查),迭代重心
  完全转向多册计划;闭源自用场景下 ARL 的回传触发条件不会命中,自用改动无需回传。
- 边界:若未来恢复公开发行或商用,须先恢复律师复核,并以新 ADR 重新评估 ARL / MIT 两侧义务;
  本 ADR 不豁免既有的归属保留义务,也不改变任何已发布版本的效力。

## 落地证据

- README「📄 许可」节:标注定位转向与复核义务挂起条件(指向本 ADR)。
- `LICENSE` / `NOTICE.md` / `LICENSE-OPENCUT.MIT`:刻意未改动(见决策 2)。
- 多册迭代计划总纲「使用定位」:个人自用/学习软件、不商业发行,与本决策一致。
